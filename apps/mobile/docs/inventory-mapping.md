# Đối chiếu chức năng web → mobile (vòng 1)

Nguồn: `~/workspace/run-logs/feature-inventory.md` (76 mục menu, 50 trang lá).
Trạng thái vòng 9: Dashboard + Users + Vai trò (đủ CRUD) + Loại claim (đủ CRUD) + Đơn vị tổ chức (đủ CRUD) + Nhật ký bảo mật (list/detail/xóa) + Phiên (list/thu hồi) + Tài khoản có màn hình thật + nhóm OpenIddict (Ứng dụng đủ CRUD, Phạm vi đủ CRUD, Ủy quyền list/detail/xóa, Token list/detail/xóa) + nhóm Quyền (Nhóm đủ CRUD, Định nghĩa đủ CRUD) + nhóm Tính năng (Nhóm đủ CRUD, Định nghĩa đủ CRUD) qua tab hub "Quản trị" (17/50 trang lá) + nhóm Cài đặt (Cài đặt hệ thống, Định nghĩa cài đặt đủ CRUD) qua cùng hub (19/50 trang lá) + nhóm Bản địa hoá (Ngôn ngữ đủ CRUD, Tài nguyên đủ CRUD, Văn bản so sánh + đặt/xóa) qua cùng hub (22/50 trang lá) + nhóm Kiểm toán/Bảo vệ dữ liệu (Loại thực thể chỉ xem, Nhật ký kiểm toán list/detail/xóa, Nhật ký hệ thống list/detail) qua cùng hub (25/50 trang lá) + nhóm Thông báo (Thông báo của tôi list/detail/đánh dấu đọc/xóa, Nhóm đủ CRUD, Định nghĩa đủ CRUD + gửi, Lịch sử gửi list/xóa/gửi lại) qua cùng hub (29/50 trang lá);
P0 OIDC đã kiểm chứng end-to-end ở tầng giao thức (authorize → login → code → đổi token PKCE, không secret);
các trang còn lại đã có route kế hoạch trong bảng này, xây dần P0→P3 các vòng sau.
Không màn hình nào dùng mock data trong production: trang chưa xây sẽ không xuất
hiện trong tab bar cho tới khi có API thật.
